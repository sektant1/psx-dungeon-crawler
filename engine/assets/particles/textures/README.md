# Particle textures

Drop a PNG in this directory. That is the whole workflow: at boot the engine
scans this folder and generates an Ogre material per file, named
`Particles/Auto/<stem>`. An effect in `particles.toml` then references the file
stem, not the material:

```toml
[[effect]]
name = "torch_fire"
texture = "ember"
```

Defaults per file: alpha blend, nearest (point) filtering, unlit, depth-write
off, no culling, no flipbook. Override any of them per stem in
`../textures.toml`.

## Conventions

- Power-of-two, small. These are PSX-era particles; 32x32 or 64x64 is plenty.
- Straight (non-premultiplied) alpha. `Particles/Auto/<stem>` uses
  `SBT_TRANSPARENT_ALPHA` (`src_alpha, 1-src_alpha`) and the sprite shader does
  a plain `texture() * particleColour`, so nothing anywhere divides or
  multiplies by alpha.
- **Additive art is the exception worth remembering.** `blend = "additive"` is
  `SBT_ADD` (`one, one`), which ignores alpha completely. An additive texture
  must therefore encode its falloff in *RGB brightness* and reach pure black at
  its edges; its alpha channel only feeds the shader's `alphaScissor` discard.
  A bright-white pixel at alpha 0.1 in an additive texture still adds at full
  strength.
- Flipbooks are a single atlas image, frames laid out left to right then top to
  bottom, with `rows`/`cols`/`fps` declared in the overrides.
- The stem is the public name. Renaming a file renames the texture everywhere,
  so keep them short and descriptive: `ember`, `smoke`, `spark`, `blood_drop`.

## The committed set is placeholder art

Every PNG here is **programmer art generated by a script**, not authored, and is
expected to be replaced. Do not repaint one by hand — edit the generator and
re-run it, or the next regeneration silently reverts your work.

```sh
python3 tools/gen_particle_textures.py
```

The script is deterministic (the seed is at the top of the file), so re-running
it with no source change rewrites byte-identical files and produces no diff.

| Stem | Size | Use | Override |
| --- | --- | --- | --- |
| `spark` | 32x32 | wand and claw muzzle sparks | `additive` |
| `ember` | 32x32 | torch fire, embers, glowing motes | `additive` |
| `flame_sheet` | 128x128 | looping flame, 4x4 frames of 32x32 | `additive`, flipbook 4x4 @ 16fps |
| `smoke` | 64x64 | impact puffs, dissipation | alpha |
| `blood_drop` | 32x32 | fine blood spatter | alpha |
| `blood_splat` | 64x64 | projected blood decals and pools | alpha |

`smoke` does **not** set `soft_fade`. The flag parses and the shader variant
compiles, but nothing can bind it until the compositor grows a depth copy
target (see `docs/particles.md`, "Known gaps"), so enabling it here would only
look like a working feature.

Sizes follow the convention above: authored at half resolution and
nearest-upscaled by 2, which guarantees a 2x2 minimum feature and keeps a hard
pixel edge under any magnification.
