Learning Vulkan without losing a month

An ordered curriculum, what to skip because a library already does it, and where every chapter lands in eng::rhi.

On these links

Written from knowledge, not fetched — check anything that 404s against vulkan.org/learn, which aggregates the current canonical locations. Khronos has been consolidating everything under docs.vulkan.org, so a dead link usually has a live twin there.

§1Two schools, and which one you want

Vulkan teaching material splits into two traditions, and picking wrong costs you weeks.

vulkan-tutorial teaches the API bottom-up: every struct, every field, in one long main.cpp. It is the best explanation of what the objects are and the worst model for how to structure an engine — its resource handling is deliberately naive and its final program is unshippable by design.

vkguide teaches engine-shaped Vulkan: modern from the start (dynamic rendering, sync2, VMA, descriptor abstractions, a deletion queue), organised as systems rather than a script. Its architecture is much closer to what Device.h asks for.

Do both, in that order, and treat the first as vocabulary and the second as grammar. Skimming vkguide before you have typed vulkan-tutorial's triangle produces the illusion of understanding; doing vulkan-tutorial and stopping produces a backend you have to rewrite.

§3Synchronization: the part no library removes

vk-bootstrap removes setup. VMA removes allocation. Nothing removes synchronization, and it is where a renderer is actually won or lost. Give it a dedicated pass rather than absorbing it incidentally.

  • Yet another blog explaining Vulkan synchronization themaister.net/blog/2019/08/14/yet-another-blog-explaining-vulkan-synchronization/ Hans-Kristian Arntzen. The single best explanation of execution vs. memory dependencies. If you only read one thing here, read this — twice.
  • Khronos Synchronization Examples github.com/KhronosGroup/Vulkan-Docs/wiki/Synchronization-Examples A cookbook of correct barriers for the exact situations you will hit: staging upload, render-target → sampled, swapchain present. Copy from here, don't improvise.
  • Understanding Vulkan Synchronization khronos.org/blog/understanding-vulkan-synchronization Official companion to VK_KHR_synchronization2, which is what you should target — the sync2 barrier structs are meaningfully harder to get wrong.
The rule that saves you

Every validation-layer message about synchronization is a real bug, including the ones that appear on a frame that looks correct. Enable VK_LAYER_KHRONOS_validation with the synchronization validation feature switched on, and route its callback into eng::log at error level so it lands in the same console as everything else. The engine already treats a missing material as a loud error rather than a silent fallback — hold the GPU to the same standard.

§5Reference shelf

  • The Vulkan specification registry.khronos.org/vulkan/specs/latest/html/vkspec.html · mirror: docs.vulkan.org/spec/latest/ Not for learning — for settling arguments. Every struct's "Valid Usage" list is exactly what the validation layer checks, so when a layer message is cryptic, find the VUID it names in the spec and read the clause.
  • Vulkan 1.1 quick reference guide — already in this repo docs/vulkan11-reference-guide.pdf The fold-out card. Still the fastest way to look up a struct's shape. Caveat: it predates dynamic rendering and sync2, both of which you are targeting — trust it for core objects, not for the modern frame loop.
  • OpenGL 4.6 quick reference card — also in this repo docs/opengl46-quick-reference-card.pdf Useful in the other direction: the existing shaders and the GL3Plus path are what you are reproducing, so this is the reference for the behaviour you must match.
  • vulkan.gpuinfo.org vulkan.gpuinfo.org Before you rely on a format, limit or extension, check what fraction of real hardware reports it. Answers "can I just require Vulkan 1.3?" with data.
  • LunarG SDK documentation vulkan.lunarg.com/doc/sdk Validation layer configuration, vkconfig, and the layer settings file. Read the validation layer page once so you know which extra checks exist (sync validation, best practices, GPU-assisted) and how to switch them on.

§6Read other people's engines

At some point the remaining questions are architectural — "where does that live?" — and the answer comes from reading a real renderer rather than a tutorial.

  • zeux/niagara github.com/zeux/niagara A Vulkan renderer built from scratch on video, with the commit history to match. Small enough to read in an evening. The closest thing to watching an expert make the decisions you are about to make.
  • KhronosGroup/Vulkan-Samples github.com/KhronosGroup/Vulkan-Samples Official, and unusually well documented — each sample has a README explaining the technique, not just the code. The dynamic rendering and descriptor indexing samples are the relevant ones here.
  • SaschaWillems/Vulkan github.com/SaschaWillems/Vulkan The reference collection: ~100 focused examples. Use it as a lookup — "how does anyone do X" — rather than reading front to back.
