Building eng::rhi::vulkan

Dependency choices, CMake wiring, a file layout, and a method-by-method map from the contract you have to the Vulkan you'll write.

§1Rules of the seam

Three constraints define this work. They are already true in the repo, and every design decision below follows from them.

  • No Vulkan type crosses engine/include/eng/rhi/. Types.h says so in its own header comment, and it is what lets the rest of the engine compile untouched while you work.
  • eng_rhi cannot see the renderer. It sits beside eng_platform deliberately (CMakeLists.txt:177-189). Do not reach for RenderCore, OGRE, or anything in eng_systems.
  • The backend must fail loudly and return null when it cannot run — that is the documented behaviour of createDevice, and it is what keeps rhi_contract_tests green on machines without a GPU.

§2Dependencies: what to let someone else write

Yes to vk-bootstrap. The boilerplate it removes — instance creation, layer and extension juggling, physical device selection with feature requirements, queue family lookup, swapchain construction — is several hundred lines that teach you the shape of the API exactly once and then become a maintenance tax forever. It is a build-time-only dependency confined to two .cpp files, so it never appears in a header and can be removed later without touching anything above it. The one caveat: read what it does before you use it, or you will not understand your own device's feature set.

LibraryVerdictWhy
vk-bootstrap
charles-lunarg/vk-bootstrap		 Take it Instance/device/swapchain setup. Kills ~600 lines with zero architectural commitment. Its SwapchainBuilder also handles the recreate path you would otherwise get wrong.
VMA
GPUOpen-LibrariesAndSDKs/VulkanMemoryAllocator		 Take it Non-negotiable. Manual VkDeviceMemory sub-allocation is a project in itself, and getting it wrong shows up as fragmentation and out-of-memory on other people's GPUs, not yours.
volk
zeux/volk		 Skip for now Meta-loader for function pointers. Real benefit (avoids loader dispatch overhead) but it is a micro-optimisation at this stage and it complicates every call site. Add it after the frame loop is stable — it is a mechanical change. Note OGRE vendors its own copy inside its Vulkan RS, which you are not building, so there is no conflict either way.
glslang / shaderc CLI only Compile GLSL → SPIR-V offline in the asset pipeline. ShaderDesc::code takes bytes, so runtime compilation buys nothing but startup cost and a heavy link. Already installed here at 16.3.0.
SDL2 Already in the build Use SDL_Vulkan_GetInstanceExtensions and SDL_Vulkan_CreateSurface rather than platform surface code — DeviceDesc already carries platformWindow as an SDL_Window* for exactly this.

§3CMake wiring

Keep Vulkan optional so a machine without the SDK still builds the engine — the backend returning null is a supported state.

# cmake/Dependencies.cmake — near the other CPM entries.
# Pin real release tags; verify against upstream before committing.
find_package(Vulkan QUIET)
if(Vulkan_FOUND)
    CPMAddPackage(
        NAME vk-bootstrap
        GITHUB_REPOSITORY charles-lunarg/vk-bootstrap
        GIT_TAG v1.3.302          # check upstream tags
        OPTIONS "VK_BOOTSTRAP_TEST OFF"
    )
    CPMAddPackage(
        NAME VulkanMemoryAllocator
        GITHUB_REPOSITORY GPUOpen-LibrariesAndSDKs/VulkanMemoryAllocator
        GIT_TAG v3.1.0            # check upstream tags
        DOWNLOAD_ONLY YES         # header-only; we compile the impl
    )
    add_library(eng_vma INTERFACE)
    target_include_directories(eng_vma INTERFACE
        "${VulkanMemoryAllocator_SOURCE_DIR}/include")
endif()
# CMakeLists.txt — extend the existing eng_rhi target (currently :183-189).
option(ENG_RHI_VULKAN "Build the Vulkan RHI backend" ${Vulkan_FOUND})

add_library(eng_rhi STATIC
  engine/src/rhi/Registry.cpp
  engine/src/rhi/null/NullDevice.cpp
  engine/src/rhi/gl/GLDevice.cpp
  engine/src/rhi/vulkan/VulkanDevice.cpp)

if(ENG_RHI_VULKAN)
  target_sources(eng_rhi PRIVATE
    engine/src/rhi/vulkan/VulkanContext.cpp
    engine/src/rhi/vulkan/VulkanSwapchain.cpp
    engine/src/rhi/vulkan/VulkanResources.cpp
    engine/src/rhi/vulkan/VulkanCommandList.cpp
    engine/src/rhi/vulkan/VulkanPipeline.cpp
    engine/src/rhi/vulkan/VulkanFormats.cpp
    engine/src/rhi/vulkan/VmaImpl.cpp)  # VMA_IMPLEMENTATION alone
  target_link_libraries(eng_rhi PRIVATE
    Vulkan::Vulkan vk-bootstrap::vk-bootstrap eng_vma SDL2::SDL2)
  target_compile_definitions(eng_rhi PRIVATE ENG_RHI_VULKAN=1)
endif()

Everything Vulkan is PRIVATE. VulkanDevice.cpp keeps compiling unconditionally and returns null when ENG_RHI_VULKAN is undefined, which is the same contract it honours today — so rhi_contract_tests passes either way.

Build discipline

Adding CPM packages re-runs configure, not a rebuild — OGRE's object files survive. Build the one target: cmake --build build --target eng_rhi -j8. Never rm -rf build.

§4File layout

One concern per file, matching how the null backend is organised.

FileHolds
VulkanDevice.{h,cpp}The Device implementation and createDevice. Thin — it delegates.
VulkanContext.{h,cpp}Instance, physical device, logical device, queues, VMA allocator, debug messenger. Built with vk-bootstrap.
VulkanSwapchain.{h,cpp}Swapchain, images, views, acquire/present, recreation on resize and VK_ERROR_OUT_OF_DATE_KHR.
VulkanResources.{h,cpp}The generational handle tables and the buffer/texture/sampler/shader records behind them.
VulkanCommandList.{h,cpp}CommandList implementation: state tracking, binding, draws, debug labels.
VulkanPipeline.{h,cpp}PipelineDesc → VkPipeline, plus a hash-keyed cache and the pipeline layout / descriptor set layouts.
VulkanFormats.{h,cpp}Every enum mapping in one place: Format, BlendMode, CompareOp, CullMode, VertexFormat, FilterMode, AddressMode, topology.
VmaImpl.cppNothing but #define VMA_IMPLEMENTATION and the include. Keeps VMA's warnings out of your files.

§5Contract → Vulkan map

The whole job, in one table. Work down it.

Contract methodWhat it does in Vulkan
createDevicevkb::InstanceBuilder (validation gated on DeviceDesc::enableValidation) → surface from SDL → vkb::PhysicalDeviceSelector requiring Vulkan 1.3 with dynamicRendering and synchronization2 → vkb::DeviceBuilder → vmaCreateAllocator. Return null with a logged reason on any failure.
capabilities()From VkPhysicalDeviceProperties: deviceName, maxImageDimension2D, maxColorAttachments. maxSimultaneousLights is not a device limit — it is how many lights your descriptor layout can bind, and the contract test requires ≥ 16 because psx_lighting.glsl does.
beginFrameWait the frame fence → vkAcquireNextImageKHR → reset the frame's command pool → run its deletion queue → begin the command buffer. Return false on OUT_OF_DATE/SUBOPTIMAL after kicking recreation.
endFrameTransition the swapchain image to PRESENT_SRC → end and submit with acquire/render semaphores and the frame fence → vkQueuePresentKHR → advance the frame index.
resizeSwapchainvkDeviceWaitIdle, destroy views, rebuild via vkb::SwapchainBuilder with the old swapchain passed in.
beginPassvkCmdBeginRendering with VkRenderingAttachmentInfo per ColourAttachment (clear → LOAD_OP_CLEAR vs LOAD_OP_LOAD). Transition each attachment to COLOR_ATTACHMENT_OPTIMAL first — an invalid handle means the swapchain image.
endPassvkCmdEndRendering, plus the barrier that makes each colour target readable if a later pass samples it. The PSX chain does exactly that, repeatedly.
createBuffervmaCreateBuffer. BufferUsage::Dynamic → HOST_VISIBLE|HOST_COHERENT with persistent mapping; everything else DEVICE_LOCAL + a staging copy for initialData.
updateBufferDynamic: memcpy into the mapped ring (the contract says this must not stall — so sub-allocate per frame, never overwrite in place). Static: staging buffer + vkCmdCopyBuffer + barrier.
createTexture / updateTexturevmaCreateImage, staging buffer, UNDEFINED → TRANSFER_DST, vkCmdCopyBufferToImage, → SHADER_READ_ONLY_OPTIMAL. Track the current layout per image; you will need it in beginPass.
createSamplerDirect mapping. FilterMode::Nearest is the default and the PSX look depends on it — do not "helpfully" enable linear or anisotropy.
createShadervkCreateShaderModule over ShaderDesc::code. Validate the SPIR-V magic number (0x07230203) and reject GLSL text with a clear message — the contract explicitly requires failing at creation, not at first draw.
createPipelineThe big one. VkGraphicsPipelineCreateInfo with VkPipelineRenderingCreateInfo fed from colourFormats/depthFormat, viewport and scissor as dynamic state, blend from the four BlendMode values.
bindPipeline/setViewport/setScissorvkCmdBindPipeline, vkCmdSetViewport, vkCmdSetScissor. See Hazards §1 on the negative-height viewport.
bindVertexBuffer/bindIndexBuffervkCmdBindVertexBuffers, vkCmdBindIndexBuffer with INDEX_TYPE_UINT32 — the contract mandates 32-bit indices.
bindUniformBuffer/bindTextureDescriptor writes. See §8 — this is a design decision, not a translation.
pushConstantsvkCmdPushConstants. Real push constants; the 128-byte budget in the contract is the guaranteed minimum maxPushConstantsSize.
draw/drawIndexedvkCmdDraw/vkCmdDrawIndexed, after flushing any pending descriptor binds.
pushDebugGroup/popDebugGroupvkCmdBeginDebugUtilsLabelEXT/End. Do this early — named regions are what make a RenderDoc capture legible, and docs/debugging-renderdoc.md assumes they exist.
waitIdlevkDeviceWaitIdle, then drain every deletion queue.

§6The frame loop

Two frames in flight. Everything per-frame lives in one struct, which is what makes the lifetime question answerable.

// Sketch. Two is the right number here: enough to overlap CPU and GPU,
// few enough that the dynamic-buffer ring stays small.
struct FrameContext {
    VkCommandPool     pool;        // reset whole, never per-buffer
    VkCommandBuffer   cmd;
    VkSemaphore       acquired;    // swapchain image ready
    VkSemaphore       rendered;    // safe to present
    VkFence           inFlight;    // CPU waits on this before reuse
    DescriptorArena   descriptors; // reset each frame, see §8
    RingBuffer        uniforms;    // host-visible, sub-allocated per bind
    std::vector<PendingDelete> graveyard;
};

beginFrame waits on inFlight, and that wait is the moment when everything the frame owned two frames ago is provably dead: reset the pool, reset the descriptor arena, and drain the graveyard. No reference counting, no ambiguity.

§7Handles and deletion

Take the generational Table<Handle, Record> from engine/src/rhi/null/NullDevice.cpp:15-73 more or less verbatim. It already implements what the contract demands — 1-based ids, generation bump on destroy, stale-handle detection that logs instead of dereferencing — and using the same structure means a bug reproduces identically on the null backend, where it is trivial to debug.

The one change Vulkan forces: destroy* cannot destroy. The GPU may still be reading the resource. So destroyBuffer bumps the generation immediately — callers must see the handle go stale now — and pushes the actual vmaDestroyBuffer onto the current frame's graveyard, executed two frames later.

void VulkanDevice::destroyBuffer(BufferHandle h)
{
    BufferRec* rec = mBuffers.get(h, "buffer");
    if (!rec)
        return;                       // already logged by the table
    mFrames[mFrameIndex].graveyard.push_back(
        [buf = rec->buffer, alloc = rec->allocation, this] {
            vmaDestroyBuffer(mAllocator, buf, alloc);
        });
    mBuffers.destroy(h, "buffer");    // generation bumps here
}

§8Descriptors

bindTexture(slot, …) and bindUniformBuffer(slot, …) read like GL binding points, and that mismatch is the single largest design gap between the contract and Vulkan. Three strategies, in ascending order of effort:

StrategyCostWhen
Per-draw sets from a per-frame pool. One VkDescriptorSetLayout with a fixed slot count (say 8 UBOs + 16 samplers), allocate and write a set per draw, reset the pool each frame. Simplest. Wasteful, but a PSX-resolution frame is not descriptor-bound. Start here. It maps to the contract literally and gets you drawing.
Hash and cache. Same layout, but hash the binding state and reuse sets across draws and frames. An afternoon on top of the above. When a capture shows descriptor writes in the profile.
Bindless. One large descriptor array, indices via push constants. Real design work; changes how shaders are written. Not now. It contradicts the current shader set and buys nothing at this scale.

Whichever you pick, the 16-sampler figure is not arbitrary: capabilities() must report maxSimultaneousLights >= 16, and RenderCore already forces setMaxSimultaneousLights(16) on every pass because psx_lighting.glsl binds 16 light slots. Whatever layout you design has to carry that many.

§9Shaders and SPIR-V

ShaderDesc::code is bytes, and for Vulkan those bytes are SPIR-V. That makes shader compilation an asset pipeline step, which is the right place for it: the engine already cooks scenes (make cook), and shaders join that pattern rather than inventing a new one.

# The offline step. glslangValidator 16.3.0 is already installed.
glslangValidator -V --target-env vulkan1.3 \
    -DLIT -DMETAL \
    -o build/shaders/psx_lit_metal.frag.spv \
    assets/shaders/psx.frag

Two things follow immediately, and both are covered in Hazards §2: the -D variant explosion in psx.program wants specialization constants instead, and GLSL 330's default-block uniforms are illegal in SPIR-V. Do not start this until stage 5 — get a triangle with a hand-written Vulkan-GLSL shader working first, so that when the port misbehaves you know the backend underneath it is sound.

§10Proving it works

The contract test, headless

engine/tests/RhiContractTests.cpp:111-114 builds a DeviceDesc with width=640, height=360 and no window — nativeWindowHandle is 0 and platformWindow is null. Two valid responses:

  • Return null with a logged reason. The test prints vulkan: not available and passes. Correct, and worthless as coverage.
  • Detect the missing window and create a headless device. This machine's Vulkan instance advertises VK_EXT_headless_surface, so the full create/draw/destroy sequence — every resource path, the deletion queue, waitIdle — runs in CI with no display.

Do the first to unblock stage 2, then the second at the end of stage 3. The second is what stops the backend from silently rotting.

The sample app

Add rhi_triangle under samples/, alongside psx-demo. It owns its own SDL window created with SDL_WINDOW_VULKAN, which is why it must be a separate binary from game — see Hazards §4. Give it the engine's screenshot hook (RAVEN_SCREENSHOT / RAVEN_SCREENSHOT_FRAME) on the first day; it is how every later stage gets verified without a human looking at a window.

The checks that catch things early
  • ctest -R rhi_contract — the sequence completes on Vulkan.
  • Validation layers silent for a 10,000-frame run of rhi_triangle, including a window resize and a minimise/restore.
  • make renderdoc APP=rhi_triangle — a capture opens and the debug labels from pushDebugGroup are legible.
  • No leaked handles at shutdown: log liveCount() per table in the destructor, the way the null backend already can.
